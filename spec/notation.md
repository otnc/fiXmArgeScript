# 表記

ソースコードでは、キーワードを記号なしの英数字で書きます。ビルドすると、キーワードを辞書どおりの正式な綴りに直したファイルができます。この仕様書では、ソースを「下書き」、ビルドしたファイルを「清書」と呼びます。

キーワードから記号と空白を抜いて小文字にした形を「骨格」と呼びます。辞書の264語は骨格どうしがぶつからないので、骨格から正式な綴りに一意に戻せます。

| 正式な綴り | 骨格 (下書きに書く形) | 抜くもの |
| --- | --- | --- |
| `Iz'u` | `izu` | `'` |
| `S~ond'` | `sond` | `~` と `'` |
| `Syu Tain` | `syutain` | 空白 |
| `Kei-P` | `keip` | `-` |
| `Vani·tA` | `vanita` | `·` |

記号を書かないので、`'` が文字列の引用符と、`-` が引き算とぶつかりません。空白を含む語も1語として書けるので、字句解析が単純になります。

## 規則

1. 下書きに書けるのは、英数字、`_`、演算子の記号、コメントの `#`、`"` で囲んだ文字列です。文字列とコメントの中には、日本語も含めて何でも書けます。
2. 下書きのキーワードは小文字で書きます。`IZU` のように大文字を含むと構文エラー (`AyAmis`) です。清書では、辞書どおりの大文字と小文字 (`Iz'u`、`AccUhEarts` など) になります。
3. 変数名や関数名には、キーワードの骨格と同じ名前を使えません。大文字と小文字だけが違う名前 (`Izu` など) も、紛らわしいので使えません。
4. 拡張子は、下書きが `.fxma`、清書が `.fxmac` です。インタプリタが実行するのは清書だけなので、下書きは必ずビルドしてから実行します (`fixmarge keeon` はメモリ上でビルドしてそのまま実行します)。清書を読み込むときは正式な綴りしか受け付けず、方言や骨格は通りません。
5. ビルドは何度かけても同じ結果になります。清書では行頭のインデントを消します。ブロックは `finend` で閉じるので、インデントがなくても意味は変わりません。ただし、`"""` で囲んだ文字列の中のインデントは文字列の一部なので残します。エディタも清書のファイルではインデントしません。
6. 標準パッケージの関数名や辞書のキーのうち、JavaScript で複数の語からなる名前 (`isAbsolute` など) は、辞書の語を JavaScript と同じ順に camelCase でつなぎます (`izuDefutai`)。部品にはキーワードの語も使えます。清書では、部品ごとに正式な綴りに直してつなぎます (`Iz'udeFuTai`)。部品に分けて扱うので、同じ語をほかの名前の部品にも使えます。

## 方言と表記ゆれ

辞書と違う綴り (表記ゆれ) もエラーにせず、方言として受け付けます。作詞者の SLAVE.V-V-R 氏が、発音の違いを「方言の分岐の原初」のようなものだと説明しているためです。

- **標準語**: 辞書 CSV の綴りです。正式な綴りはこれです。
- **方言**: 別の綴りの骨格を、標準語の骨格の別名として登録します。例: `lowhel` → `lowhell`、`prizujeen` → `prisjeen`。
- **警告**: 方言で書いても実行できますが、`DowGuil lowhel → LowhEll` のような警告が出ます。
- **ビルド**: 清書では標準語に直ります。
- **しないこと**: 編集距離などで似た綴りを推測することはしません。打ち間違いが別の語として通ってしまうのを防ぐためです。

語を足したときに骨格がぶつからないかは、CI で確かめています。
