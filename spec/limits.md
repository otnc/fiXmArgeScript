# 深さと大きさの上限

どんなプログラムを渡されても、インタプリタ自身が落ちたり固まったりしないように、次の上限を置きます。超えると `Bavellabion` です。実行中に超えたものは `youlugive` で捕まえられます。

| 上限 | 値 | 理由 |
| --- | --- | --- |
| 関数の呼び出しの深さ | 10000 | JavaScript のスタックの上限や Python の再帰の上限と同じ役目 |
| 呼び出し中の関数の本体の深さの合計 | 20万 | 実行は構文木を再帰でたどるので、本体の深い関数が深く呼び合うと、呼び出しが10000に届く前にスタックを使い切る。本体の深さが20段までの関数なら、先に呼び出しの上限に届く |
| 構文木の深さ (括弧・ブロックの入れ子、`1 + 1 + ...` のように続けた演算子) | 10000 | 構文解析も検査も整形も再帰でたどる |
| 文字列の `#{}` の中に文字列を書く深さ | 100 | 中の文字列は外側を読むたびに読み直す |
| マクロの展開 | 深さ64、字句100万個 | 引数を何度も使うマクロを入れ子で呼ぶと、展開が何倍にもなる |
| 文字列とバイト列 | 1GiB | メモリを取り切る前に止める。JavaScript が長すぎる文字列で `RangeError: Invalid string length` を投げるのと同じ。`"a" * n` のように長さを数で決めるものも、`s + s` や `"#{s}#{s}"` のようにつないで作るものも、`redogh` や `json no salook` で文字列にした形も同じ上限 |
| つないで作る配列 (`xs + ys`、`xs no 0...0 izu ys`) | 要素 67108864個 (2の26乗) | 文字列の上限と同じ1GiB分。繰り返すと1回ごとに倍になる |

配列と辞書の入れ子に上限はありません。出力するときと比べるときは再帰を使わないので、いくら深くても動きます。JSON にするときだけは、深さ10000で `imJune` です。

実行の長さには、普段は上限がありません。Node.js と同じく、`tadact azagara` のような止まらないプログラムは、止めるまで動き続けます。止めたいときは `--laikill` (`LAikIll`、生きる。英語の別名は `--steps`、短い形は `-l` と `-s`) で、実行する文と繰り返しの数の上限を付けます。

```
fixmarge keeon --laikill 1000000 main.fxma
fixmarge coatain --laikill 1000000
```

- 数えるのは、実行した文と、繰り返し (`azagara`) の周回です。本体が空の繰り返しも周回で数えます。
- 上限を超えると `Bavellabion` で、対象は `LAikIll` です。`youlugive` で捕まえても、次の文でまた `Bavellabion` になるので、その先には進めません。
- バックトラックでやり直した分も足して数えます。選択肢を総当たりする探索が終わらないときも止まります。
- `fixmarge coatain` ではファイルごとに数えます。
- `0` は上限なしです。負の数は書けません。
- 待っている時間 (`toim no saimoku` や通信) は数えません。
- WebAssembly 版では `run` の `maxSteps` で同じ上限を付けます。ブラウザでは実行中のプログラムを外から止められないので、プレイグラウンドはいつも500万の上限を付けています。
